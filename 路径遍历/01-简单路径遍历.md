# Lab：File path traversal, simple case

> 难度：APPRENTICE ｜ 分类：路径遍历 ｜ 状态：📖 解析（待本人实操验证）
> 官方页面：https://portswigger.net/web-security/file-path-traversal/lab-simple

## 一、漏洞原理

图片加载接口把用户传入的文件名直接拼到基础目录后面读文件：

```
<img src="/loadImage?filename=218.png">
→ 服务端读取 /var/www/images/218.png
```

`../` 在路径里表示向上一级，连续使用就能跳出基础目录。根因不是"没过滤点号"，而是**信任了用户输入去构造文件系统路径**。除了读任意文件，部分场景还能写文件进而控制服务器。

## 二、标准利用链

```
/loadImage?filename=../../../etc/passwd
```

服务端实际读取 `/var/www/images/../../../etc/passwd` → 落到 `/etc/passwd`。`../` 的个数取决于基础目录深度，从 1 开始递增直到响应里出现 `root:x:0:0` 之类的内容。Windows 目标两种分隔符都有效：`..\..\..\windows\win.ini`。

**常见绕过**（对应后续 PRACTITIONER labs）：

| 防御写法 | 绕过 |
|---|---|
| 直接剥掉 / 拦截 `../` | 绝对路径 `filename=/etc/passwd` |
| 只删一次遍历序列 | 嵌套 `....//`（删掉内层后还原成 `../`）、`....\/` |
| 前置 WAF / 服务器解码一次 | URL 编码 `%2e%2e%2f`、双重编码 `%252e%252e%252f`、非标准编码 `..%c0%af` |
| 要求路径以基础目录开头 | `/var/www/images/../../../etc/passwd` |
| 要求以 `.png` 结尾 | 空字节截断 `../../../etc/passwd%00.png` |

## 四、防御视角

官方给的是**两层防御**：

1. 最有效的是**根本不把用户输入传给文件系统 API**——多数这类功能都能改写成按 ID 映射读取；
2. 做不到时：先用白名单校验输入（或至少只允许字母数字），拼好路径后调用平台 API **规范化（canonicalize）**，再校验规范化后的路径是否仍以预期基础目录开头。

```java
File file = new File(BASE_DIRECTORY, userInput);
if (file.getCanonicalPath().startsWith(BASE_DIRECTORY)) { /* process */ }
```

**常见错误**：只 `replace("../", "")`（`....//` 一删就还原）、只检查未规范化的 `startsWith`（`base/../../etc` 也能过）、只过滤相对路径而漏掉绝对路径与编码形式。

## 五、一句话复盘

"路径遍历的根因是拿用户输入拼文件路径，`../` 跳出基础目录就能读任意文件，绕过过滤常用绝对路径、双写或编码。修复要先把路径规范化再校验是否仍在基础目录内，最干净的做法是根本不暴露文件名、改用 ID 映射。"
